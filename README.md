# MerchantAI

MerchantAI is a React/Vite business dashboard with Supabase authentication, inventory, invoices, transactions, reports, and a rule-based business assistant. AI and Solana payments are demo features.

## Run locally

The MerchantAI Supabase project is configured in `.env.example`; its browser-safe publishable key is included. No paid AI key is required.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

On Windows PowerShell, use `Copy-Item .env.example .env.local` instead of `cp`. Run commands in the repository root. Restart Vite after changing environment variables. For hosting, copy the two VITE_ values into your build environment before building.

Register your account. If email confirmation is enabled, confirm the email and then sign in. After signing in, open Settings > Load Demo Data to populate your business with synthetic examples.

## Connected backend

- Project: MerchantAI (`ftksaidplrdqlmtjkrld`)
- API URL: https://ftksaidplrdqlmtjkrld.supabase.co
- Database schema, row-level security policies, financial RPCs, and reports are installed.
- `seed-demo` is deployed with JWT verification enabled and also checks the caller through Supabase Auth.
- Profile creation is restricted to the owner of the target business. Application RPCs run as SECURITY INVOKER, so row-level security remains effective.
- Anonymous callers cannot query application tables or execute application RPCs.

Do not rerun initial migrations against this configured database. A new, empty backend can be initialized by applying every SQL file in `supabase/migrations` in filename order. Hosted migration versions were generated by Supabase during setup; if you later use CLI migration deployment against this existing project, reconcile migration history first instead of blindly running `db push`.

## Troubleshooting

- Setup screen: copy `.env.example` to `.env.local` in the repository root.
- Invalid API key: use the URL and an active publishable/legacy anon key from the same project, then restart or rebuild.
- Invalid login credentials: confirm your account's email, or reset your password in Supabase.
- Business profile missing on an account created by the original app: an administrator must complete its profile if no signup metadata was saved.
- Hosted email links: configure Auth > URL Configuration for your eventual website URL. No production website has been deployed as part of backend setup.
- Demo seed data is synthetic, and Solana payments are simulated. Do not treat simulated payments as real settlement.

Keep service_role and sb_secret_ credentials server-side. Never put them in VITE_ variables.
